# 数据集构建

[English](README.md)

### 目的与边界

本目录公开玛拉妮 chat-v2 LoRA 使用的完整数据集设计和构建器，但不直接包含
提取后的游戏语料或最终 train/validation/test 文件。使用者提供自己在本地
取得的 `YuanShenResources` 仓库，脚本即可按照相同格式和切分政策确定性构建
数据。

公开的虚构样本用于展示最终格式，不复刻游戏对白。生成数据写入被 Git 忽略的
`dataset/work/`。

### 构建

指定源仓库后运行：

```bash
YUANSHEN_RESOURCES_DIR=/path/to/YuanShenResources \
  dataset/build.sh
```

常用覆盖项：

```bash
INCLUDE_BWIKI_VOICE=0                 # 跳过固定版本的角色语音导入
BWIKI_VOICE_REVISION=611723           # 指定已经审查的语音页面版本
CONTEXT_TURNS=8                       # 最多保留的结构化前文轮数
DATASET_LANGUAGE=zh                   # 支持时可选 zh、en 或 bilingual
DATASET_PROFILE=chat-v2               # chat-v2 或 legacy
TRAVELER_GENDER=male                  # 全部性别分支使用同一个主角选择
VALIDATION_RATIO=0.05 TEST_RATIO=0.05
SPLIT_SEED=mualani-sft-v1
```

最终行格式位于 `schemas/sft_row_v1.schema.json`，已采用的构建配置位于
`config/mualani_chat_v2.json`。

### 构建阶段

1. 递归扫描中英文对白 JSON，通过说话人识别玛拉妮，并最多保留八个结构正确的
   前置对话轮次。
2. 先保存全部出现位置用于审计，再按稳定对白 ID 去重；重复时优先使用独立的
   任务或活动文件，而不是汇总文件。
3. 可选获取固定版本的玛拉妮角色语音页，把语音分成资料、天气、时间、好感、
   食物、生日和战斗等类别，再按规范化文本去重合并。
4. 解析游戏标记。`{NICKNAME}` 统一替换为“旅行者”或 `Traveler`；全部男女
   分支按一个指定主角性别解析，并清除 RUBY 与格式控制标记。
5. 把连续的玛拉妮字幕片段合并成一个完整 assistant 回答，避免模型学会在语气词
   或半句话后停止。
6. 对剧情对白保留场景和此前说话人，并明确标记必须回应的最后一句。其他角色
   台词只作为条件上下文，只有玛拉妮回答属于 completion。
7. 删除没有上下文的剧情片段、战斗喊话、纯语气词、无语义的最后一句、内心
   独白选项、残句结尾和已知语义错配。
8. 完整场景只能进入一个 split。若不同场景存在完全相同且有实质内容的回答，
   会先把这些场景并入同一连通组，再进行哈希切分，防止答案跨训练、验证和测试
   泄漏。
9. 生成 SHA-256 清单，并全量检查格式、文本清洁度、性别分支、跨 split 泄漏和
   质量审查标记。

### 为什么使用完整对话上下文

只训练玛拉妮的孤立台词只能学习措辞，却会丢失每句话究竟在回应什么。因此
chat-v2 会把其他角色此前说的话放在 user 侧作为条件，但只对玛拉妮的 completion
计算损失。上下文有长度上限，并明确标出必须回应的最后一句，从而降低模型回应
更早提议或替其他角色发言的概率。

角色资料语音没有自然前文，因此构建器会根据语音类别生成简短、意图明确的
旅行者提问。战斗喊话不会被转换成普通聊天样本。

### 损失与截断

训练加载器显式渲染 ChatML。system 和 user token 的标签都设为 `-100`，只对
assistant 内容计算损失。样本超过最大长度时，优先保留人物设定和回答目标，
从 user 侧最早的上下文开始截断。只有在保留最小提示结构后仍超长，才会截断
completion；所有截断数量都会写入训练运行清单。
